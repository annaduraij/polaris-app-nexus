# Repository instructions

For every task that changes files in this repository, commit the task's changes and push the current branch to `origin` before considering the task complete. Stage only files changed for the task; leave unrelated pre-existing work untouched. Use concise, specific commit messages. Never force-push. If the push fails, report the failure and leave the local commits intact.

## Feature documentation

Follow the [Polaris feature documentation convention](docs/features/README.md). Use lowercase `docs/features/` for implemented and verified features, with one Markdown document per feature. Keep proposed, approved-but-unimplemented, and in-progress feature sets in `docs/features/planned/`. Move a document out of `planned/` only after implementation and verification, update its status and links, and record verification evidence. Keep agreed decisions distinct from proposals and open questions. Apply this convention when creating or maintaining Polaris applications.
